# ADR-0029: Run DOをrun 1件につき1つ作成する

## 状況

Runを第2のDO種別として立てる方針は決まっているが(ADR-0015),粒度が決まっていない
binding単位に集約すると全runのノード通知が1つのDOに集中し, DOの1,000 req/sソフト上限を共有する

## 決定

run 1件につきDOを1つ作成し,`idFromName(runId)`で参照する
runIdは`<flow>:<localId>`, localIdは利用者が指定でき未指定はcuid2

## 帰結

上限がrun単位に分散し,短命なrunが大量にあっても上限に達しない
同じrunIdは必ず同じDOに解決されるので,二重開始をDO内で不可分に判定できる
runの横断検索はDOでは実行できず, D1の読み取りモデルにのみ作成できる
