# ADR-0046:cronタイムゾーンをスケジュール単位で指定する

## 状況

cron式はUTC固定で、運用上のローカル時刻と定義が一致しない
固定オフセットではDSTを扱えず、切り替え前後でローカル時刻が変わる
同じローカル時刻が2回存在する場合は、発火済みかをUTC時刻だけから判断できない

## 決定

cronごとにIANAタイムゾーンの`timeZone`を受け付け、省略時は`UTC`とする
`everyMs`はUTCインスタント間の固定間隔であり、`timeZone`を受け付けない

次回時刻の計算は`nextCronAt(spec, afterMs, timeZone?)`に置き、現在時刻と外部状態を参照しない純粋関数を維持する(ADR-0018)
UTCは従来の探索を使用し、それ以外はworkerdが提供する`Date`と`Intl.DateTimeFormat`だけでローカル暦を評価する

DST開始で存在しないローカル分は発火しない
DST終了で同じローカル分が複数のUTC時刻に対応する場合は、最初のUTC時刻だけで発火する
最初のUTC時刻より後から次回を求めた場合は、同じローカル分の2回目ではなく次のローカル候補へ進む

Scheduler DOは解決済みの`time_zone`を全行に保存する
既存テーブルには`UTC`を既定値として列を追加し、既存の`next_run_at`は再計算しない
タイムゾーンが実際に変更された場合はタイミング変更として次回を再計算する

REST APIは`time_zone`を返す
ダッシュボードのスケジュール時刻は行の`time_zone`、その他の時刻はブラウザのIANAタイムゾーンで表示する
表示にはIANAタイムゾーンと時点固有のGMTオフセットを含め、DSTで重複する時刻を区別する

## 帰結

cron式を運用上のローカル時刻で記述できる
タイムゾーンの規則更新はworkerdの`Intl`データに従う
DST終了時は絶対時間として1時間以上発火しない区間が生じる場合がある
