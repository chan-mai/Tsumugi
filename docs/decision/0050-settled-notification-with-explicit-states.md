# ADR-0050: 終端の通知は対象の状態を明示して投入する

## 状況

外部へ知らせる設定はonFailure(ADR-0043)のみで、対象はFAILEDとSTALLEDに限られる(#96)
完了や取り消しを外部システムへ連携する処理はperformerの末尾へ個別に書くことになり、performerが増えるほど重複する

## 決定

onFailureと同じアウトボックスの仕組みを終端の4状態(COMPLETED / FAILED / CANCELLED / STALLED)へ広げ、`onSettled: { binding, states }`として持つ
対象の状態statesは明示必須とし既定値を持たない
COMPLETEDは件数が多く、通知自体がジョブとして投入されるため、暗黙に含めると完了と同数のジョブが増える

記録先はfailure_notifyと分離したsettled_notifyに持つ
共用は片方の宛先への投入失敗がもう片方の送信を停止させる

宛先未設定と対象外の状態は記録自体を行わない, COMPLETEDを対象にした時の書き込み増加を防ぐ
宛先と対象は常に一体で更新されるため1つの設定キー(settled_target)で届ける, 配送はfailureBindingと同じ(ADR-0043)

循環の防止は非対称の除外で行う
onSettledの送信はonSettled宛先自身とonFailure宛先の両方のbindingの遷移を対象外とし、onFailureの送信は従来どおり自身のみを除外する
宛先自身の除外は自己循環(通知ジョブの完了が次の通知を生む)を、onFailure宛先の除外は2つの宛先が互いを通知し続ける相互連鎖を止める
宛先自身の遷移は記録の時点でも除外する, 送信時だけの除外では完了のたびに不要な書き込みが残る

投入するジョブのIDは元のジョブIDの全体と試行回数に加えて状態を含める
STALLEDやCANCELLEDへの遷移は試行回数を進めず、リトライを挟んだ別の終端が同じIDになり通知が欠落する

payloadは`SettledNotice`としてFailureNoticeと別の型で持つ, 既存の型のstateを広げると利用者のperformerが壊れる
performの戻り値resultを含める, 保存上限(8,192文字)で肥大は有界

## 帰結

onFailureは併存する, 両方を設定するとFAILED/STALLEDは両方の宛先へ届く
設定する前に記録された遷移は通知されない(記録されない), ADR-0043の破棄と同じ帰結

リトライ後に同じ状態かつ同じ試行回数で再度終端へ達した場合、前回の通知ジョブが残っている間は新しい通知が投入されない(onFailureと同じ既知の制限)
通知先は分割しない前提でshard 0へ投入する, COMPLETEDを対象にして流量が大きい場合はこのshardへ集中する
