# ADR-0042: 流量の実行時変更をREST APIから行い一時停止を別に持つ

## 状況

実行時のpolicy変更はJob DOの`configure()`だけで, REST APIにもダッシュボードにも経路が無い(#27)
障害時に特定のbindingを絞るには, 利用者がDOのstubを取得するコードを別に書くことになる
投入を止める手段も`concurrency`を0にする以外に無い

## 決定

policyを更新するRESTを足す, 渡した項目だけを今の設定へ重ね, 省略した項目は変えない
変更はbindingの全shardへ配る, 1つでも残ると投入が止まらない(ADR-0011)

一時停止は`paused`としてpolicyに持つ, `concurrency`を0にする方法は採らない
0で表すと元の値が失われ, 意図した停止か設定かも区別できない
停止中も実行中のジョブの回収とエージングは動かす, 止めると再開後に順序が崩れる

診断の`blocked`に`paused`を足す, 容量不足と停止は緩める先が違う
診断は今効いているpolicyも返す, 変更の前後を画面から確かめられるようにする

実行時の変更は`configure()`と同じく静的設定より優先する印を付ける(#6)
戻す操作も足す, 印と保存した設定を捨てて次の投入から静的設定が効くようにする

## 帰結

障害時の対処がダッシュボードで完結する, DOのstubを扱うコードを書かなくてよい
`Policy`に`paused`が増えるので, 独自にPolicyを組み立てている利用者は指定が要る

停止中はバックログが積み上がる, 保持期間の設定次第では投入前のジョブが増え続ける
再開の判断は運用者に委ねる, 自動で戻す仕組みは持たない
