# ADR-0042: 流量の実行時変更をREST APIから行い一時停止を別に持つ

## 状況

実行時のpolicy変更はJob DOの`configure()`だけで、REST APIにもダッシュボードにも経路が無い(#27)
障害時に特定のbindingの流量を制限するには、利用者がDOのstubを取得するコードを別に書くことになる
投入を止める手段も`concurrency`を0にする以外に無い

## 決定

policyを更新するRESTを追加する, 渡した項目だけを今の設定へ重ね、省略した項目は変えない
変更はbindingの全shardへ配る, 1つでも残ると投入が止まらない(ADR-0011)
届かないshardが在っても途中で止めず全shardへ試し、届かなかった番号を添えて500で返す
一部にだけ適用された状態を成功として返すと、止まっていない投入を止まったものとして扱うことになる
反映は冪等のため、同じ要求を送り直せば残りへ届く

一時停止は`paused`としてpolicyに持つ, `concurrency`を0にする方法は採らない
0で表すと元の値が失われ、意図した停止か設定かも区別できない
停止中も実行中のジョブの回収とエージングは動かす, 止めると再開後に順序が崩れる

診断の`blocked`に`paused`を追加する, 容量不足と停止は緩和する設定が違う
診断は現在適用中のpolicyも返す, 変更の前後を画面から確認できるようにする

実行時の変更は`configure()`と同じく静的設定より優先する印を付ける(#6)
戻す操作も追加する, 印と保存した設定を破棄して次の投入から静的設定が有効になるようにする

## 帰結

障害時の対処がダッシュボードで完結する, DOのstubを扱うコードを書かなくてよい
`Policy`に`paused`が増えるため、独自にPolicyを構築している利用者は指定が必要

停止中はバックログが蓄積する, 保持期間の設定次第では投入前のジョブが増え続ける
再開の判断は運用者が行う, 自動で戻す仕組みは持たない
