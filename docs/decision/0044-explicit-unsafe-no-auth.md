# ADR-0044:認証なしの開放を明示的な選択肢として用意する

## 状況

`auth`は任意のHonoミドルウェアを受け取るため、無条件で通過させるミドルウェアを渡せば認証なしで全機能が有効になる
手段が名前を持たないため、意図した開放と書き損ねた開放が差分の上で区別できない

Cloudflare Accessをルート全体へ適用している構成や`wrangler dev`での確認では、Tsumugi側の認証が二重になる

## 決定

`unsafeNoAuth()`を用意し、認証なしの開放をこの関数の呼び出しとして表す

名前に`unsafe`を含める, 差分とレビューで確実に視認できるようにする
有効な間はisolateごとに1回だけ警告をログへ出力する
`auth`の未設定は従来どおり404を返す(ADR-0013), 既定は変えない

## 帰結

開放は必ずコード上の1行として現れる, 通過させるだけのミドルウェアを自作する必要が無くなる

無認証で公開した場合,到達できる全員がジョブの内容の閲覧と投入と取り消しを行える
この判断を利用者の選択とする代わりに、名前とログと文書で危険を示す
