# ADR-0057: 読み取り範囲外の実行可能ジョブをキー単位で補う

## 状況

tickは実行可能なジョブを`ORDER BY run_after, id LIMIT 200`で読み、投入候補としている(ADR-0049)
キーの同時実行上限とキーのトークン不足は候補の除外にとどめ、他のキーとキーがnullのジョブの投入を止めない(ADR-0009, ADR-0045)
ただし除外は読み取り範囲内でのみ機能する
単一キーのジョブが先に200件以上到来すると範囲がそのキーで埋まり、後から到来した他のキーとキーがnullのジョブは範囲に入らない
空き枠があっても投入は1件にとどまり、そのキーの滞留が範囲より少なくなるまで他のジョブは投入されない

除外したキーを`NOT IN`で除いて追加で読む方法は、`job_due`を走査しながら除外したキーの行を読み飛ばす
読み取り行数が除外したキーの滞留件数に比例し、ADR-0049で解消した問題が同じ条件で再発する

## 決定

索引`job_key_due (state, concurrency_key, run_after, id)`を追加する
範囲が上限まで埋まり、範囲内の投入可能な件数の見込みが空き枠に満たない場合に限り、範囲外の候補を追加で読む

- キーがnullのジョブを、範囲内に含まれる件数の次から空き枠の件数まで読む
- 実行可能なジョブを持つ可能性のあるキーを`job_key_due`から1件ずつ列挙し、各キーの先頭からperKeyConcurrencyまで読む
- 同時実行上限に達したキーは列挙するが読まない
- 列挙は1 tickあたり200キーまでとし、続きは次のtickで前回の位置から列挙する

範囲内の投入可能な件数の見込みは、perKeyRateが有効な場合はキー付きのジョブを数えない, トークンの読み取り前に判定するため
追加した候補は範囲内の候補と合わせて、範囲内の候補と同じく実効優先度(ADR-0020), 作成順, IDの順で整列する

## 帰結

単一キーの滞留があっても、空き枠の分だけ他のキーとキーがnullのジョブを投入する
追加の読み取り行数は列挙したキーの数と空き枠の件数に比例し、滞留件数には比例しない
ジョブの状態とrun_afterの変更ごとに索引の書き込みが1行増える
列挙位置はメモリ上に持ち、DOの再生成時は先頭から列挙する
