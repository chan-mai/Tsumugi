# ADR-0041: 発火条件はノード単位で持ち判定は写像関数に置く

## 状況

ノード間の関係は`after`の依存だけで, 依存が成功しなかったノードはSKIPPEDになる(#31)
依存が失敗しても進むノード, 失敗したときだけ実行する後処理, 入力や前段の結果による経路の選択が書けない
後処理をflowの外に置くと、runの状態と実際に行われた処理が一致しなくなる

## 決定

依存の成否に対する発火条件を`trigger`としてノードに持たせる
`success`は全ての依存の成功を求め, `failure`は1つ以上の失敗を求め, `always`は成否を問わず決着だけを待つ
`failure`が数える失敗はFAILED / STALLED / CANCELLEDで、SKIPPEDは含めない
経路を選ばなかっただけのノードで後処理が動くと、分岐のたびに後処理が実行される
既定は`success`で、依存を持たないノードへの指定は成否の判定対象が無いため拒否する

経路の選択は`when`の述語で行う, 依存の戻り値と入力を受けてbooleanを返す
判定はRun DOが起動の直前に評価する, 依存の戻り値が揃うのはこの時点になる
写像関数と同じくJSON化できないため、flow定義から参照する(ADR-0030)

`trigger`は`shape`に含めてrunへ固定する, 進行判断が毎tick読むため
`when`は関数のため含めず、定義から参照する

発火条件を満たさなかったノードと`when`がfalseを返したノードはSKIPPEDにし、理由をerrorへ残す
状態の種類は増やさない, ジョブの7状態(ADR-0012)との対応が崩れる

runの状態は失敗したノードの有無で決める, SKIPPEDは含めない
経路を選ばなかっただけのノードでrunが失敗すると、分岐を書いた時点で成功しなくなる

## 帰結

失敗時の後処理をflowの中に置ける, runの状態と実際に行われた処理が一致する
後処理が成功してもrunはFAILEDのまま決着する, 上流の失敗が消えるわけではない
再開(ADR-0034)ではSKIPPEDも起動前へ戻るため、再開後の結果に応じて経路が選び直される

`trigger`が`success`以外の場合, 失敗した依存には戻り値が無い
受け取り口の型を未定義込みにして、写像関数が値の欠落を扱うよう促す

`when`の評価はRun DOのtickの中で実行される, 重い判定はtickの時間を延ばす
